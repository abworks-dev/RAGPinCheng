# 0005 - 只读外部媒体源与本地转录产物分离

- 状态：已批准并实现
- 日期：2026-08-19
- 关联功能：[外部媒体源](../features/external-media-sources.md)、[视频转录链路](../features/transcript-pipeline.md)、[受管资料库](../features/managed-content-library.md)

## 背景

大量培训视频可能长期保存在局域网文件服务器中。将这些视频复制进应用媒体目录会形成重复存储，也无法及时反映共享目录的新增、变更、缺失和不可达状态；让浏览器直接访问 UNC 路径又会暴露服务器路径并绕过现有鉴权播放器。

## 决策

1. 宿主机或容器平台负责以只读方式挂载 SMB 目录，应用不保存 SMB 用户名、密码或网络信任配置。
2. 应用只接受 `EXTERNAL_MEDIA_ROOTS_JSON` 提供的服务端根别名；数据库和 API 保存根别名与 POSIX 风格相对路径，不向浏览器返回宿主机绝对路径。
3. 外部目录使用独立的 `external_media_sources`、`external_media_entries` 和 `external_media_scan_runs`，不伪装成 `category_nodes`。只有转录稿通过现有审核、索引与发布事务后，才生成受管资料库中的 `media_transcript` 目录壳。
4. 扫描采用周期协调加手动触发。文件身份由相对路径、大小和修改时间形成稳定指纹；新增文件创建媒体候选，变更文件创建新候选，缺失文件标记不可用。源整体不可达时保留上次成功结果，不批量标记缺失。
5. 初次扫描只报告和展示结果，由管理员确认批量加入转录队列。可选的自动入队仅适用于后续扫描发现的新文件。
6. 远程原视频保持只读。播放器继续经过登录鉴权与 HTTP Range 代理；ASR 先把音频准备到本地媒体缓存，再沿用现有 Provider、Profile、Canonical 和 artifact 流程。
7. 外部媒体不能由上传失败删除或回收站永久清理流程删除。应用可以清理自身生成的本地音频缓存和转录产物，但不得修改共享目录文件。
8. 人工 Markdown 路径保持原样；Profile 仍由服务端 Scheme/Profile 白名单解析；experimental Profile 继续强制人工审核，审核、发布和索引状态继续分离。

## 影响

- `media_assets.storage_kind` 区分 `managed` 与 `external`；已有记录迁移后默认为 `managed`。
- 文件变化可能使旧正式转录稿继续可检索，但旧视频字节已不再存在，因此旧视频预览会明确不可用，直到新候选完成处理。
- 根别名未配置时功能保持关闭，不影响现有上传、人工转写、自动转写和已发布媒体。
- 文件服务器容量、SMB 权限、挂载健康和备份仍由基础设施负责。

## 回滚

- 删除或清空 `EXTERNAL_MEDIA_ROOTS_JSON` 并重新部署即可停止新扫描和登记；已有本地媒体与正式转录稿不受影响。
- 应用代码可回滚到迁移前版本；migration 27 是添加式迁移，表和 `storage_kind` 列可以保留，不要求破坏性降级。
- 若扫描或入队异常，先将对应源设为停用并保留 scan run、媒体任务和转录版本审计，不删除外部文件或正式 head。
