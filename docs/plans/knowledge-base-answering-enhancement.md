# 知识库问答增强实施方案

- 状态：阶段 1 代码完成待验证
- 风险等级：R2
- 范围：问答上下文、检索策略、回答引用、知识治理、评测和 BIM/CAD 专项能力
- 参考：MaxKB `v2` 的流程化问答、问题优化、数据集检索、Reranker、直接回复、反馈和应用配置思路
- 许可证边界：不复制 MaxKB GPLv3 源码；仅参考公开产品行为和架构思想，使用本项目现有实现独立完成

## 目标

把现有知识库从“可检索和回答”增强为可观测、可评测、可治理的企业级专业问答系统，优先解决多轮追问跑题、检索结果不稳定、引用不可验证和知识版本混用问题。

## 当前基线（阶段 0）

当前代码已经具备以下问答链路：

```text
HTTP conversation_id
  -> conversation_runtime 从数据库恢复 ChatSession
  -> query rewrite
  -> Dense + Sparse/RRF + rerank 检索
  -> 上一轮来源有限 carry-forward
  -> relevance gate
  -> 带历史的 LLM generation
  -> SSE prep/token/done/error
  -> 持久化用户问题和回答
```

已确认的实现入口：

- `api/conversation_runtime.py`：会话历史和上一轮来源恢复、流式结果持久化；
- `api/routes_chat.py`：按 `conversation_id` 处理问答请求并输出 SSE；
- `src/session.py`：统一编排 `rewrite -> retrieve -> merge -> generate`；
- `src/generate.py`：查询改写、回答消息组装、同步和流式生成；
- `prompts/rewrite_system.md`、`prompts/rewrite_user.md`：改写提示词；
- `frontend/src/api/chatStream.ts`、`frontend/src/hooks/useChat.ts`：追问请求和流式消费；
- `frontend/src/components/DebugPanel.tsx`：展示 `search_query`、历史字符数和检索阶段信息。

阶段 0 的关键发现：

1. 前端追问会继续使用同一个 `conversation_id`，后端能够从数据库恢复历史；问题不是简单的“没有携带历史”。
2. 查询改写模型收到历史，但 `rewrite_query()` 只返回字符串；改写是否成功、使用了哪一轮、置信度和失败原因均未结构化记录。
3. 改写异常时直接返回原始短问题。对于“那这个呢”“怎么处理”等输入，这会把无法检索的短句直接送入检索。
4. 改写结果没有主题一致性校验，错误改写会直接决定 RAG 检索方向。
5. 生成回答使用原始问题，检索使用改写问题；这是合理的通道分离，但前端和日志尚未完整区分原始问题、改写问题、命中来源、送入模型来源和最终引用来源。
6. 当前历史窗口、上一轮来源 carry-forward 和低置信度 gate 已存在，但还没有形成覆盖短追问、跨主题切换和改写失败的专项黄金集。
7. 当前主 worktree 的旧提交落后于 `origin/master`；本任务以最新 `origin/master` 为基线，避免把旧版本现象误判为当前实现事实。

阶段 0 验收标准：

- 能用脱敏问题复现并记录一轮完整链路；
- 至少区分原始问题、`search_query`、fresh sources、final sources 和最终引用；
- 明确改写失败、短追问、跨主题追问和无答案问题的现有行为；
- 建立后续阶段使用的多轮追问测试样例和指标字段；
- 阶段 0 不改变生产问答行为。

## 分阶段实施

### 阶段 1：追问上下文增强

目标：让短追问能够稳定继承上一轮主题，无法判断时主动澄清。

当前进度（2026-08-25）：

- 已新增结构化 `QueryResolution`，同时保留原有 `search_query` 兼容字段；
- 已增加短追问的上一轮问题锚定兜底；
- 已增加无法识别对象时的 `clarification_required` 路径，跳过检索和生成；
- 已向 SSE `prep` 暴露问题类型、置信度、引用轮次和兜底原因；
- 已在调试面板展示问题类型、置信度和兜底原因；
- 已约束改写 Prompt 不得引入历史中不存在的对象和参数；
- 已补充首轮、正常改写、短追问兜底、含糊追问澄清和重复问题测试；
- 尚待使用脱敏真实业务问题完成用户验收，不能据此声称生产追问准确率已经改善。

计划：

- 将查询改写结果从字符串升级为结构化对象：原始问题、独立问题、是否追问、引用轮次、置信度、兜底类型和失败原因；
- 增加完整问题、指代追问、补充条件、比较问题、主题切换和无法判断分类；
- 对短追问使用“上一轮问题 + 当前追问”兜底，不直接检索原始短句；
- 对改写结果做主题一致性和长度校验；
- 无法可靠判断时返回澄清问题，不调用无关知识生成回答；
- 在 SSE `prep` 和调试面板中显示可脱敏的改写结果和策略；
- 增加多轮追问专项测试。

不做：不复制 MaxKB 的代码，不改变索引 Schema，不引入 Agent 工作流。

### 阶段 2：检索策略和置信度增强

目标：减少无关资料进入生成模型，并让不同类型问题使用合适的检索策略。

计划：

- 统一 Dense、Sparse、RRF、Reranker、精确匹配和来源 carry-forward 的策略配置；
- 按知识库或分类配置 Top K、阈值、Reranker 和上下文预算；
- 区分精确命中、正常命中、低置信度和无命中路径；
- 为规范编号、条款号、FAQ 和固定制度增加精确匹配或直接返回策略；
- 记录检索命中、重排后、送入模型和最终引用四类来源集合；
- 保持原始查询通道，避免查询增强损害规范编号和精确参数召回。

### 阶段 3：回答和引用可靠性增强

目标：使回答中的事实可追溯到明确来源和版本。

计划：

- 强化事实与引用绑定；
- 显示文档版本、页码、章节、表格范围和视频时间戳；
- 对无来源、低置信度和来源冲突执行明确拒答或提示；
- 增加引用原文预览、高亮和引用问题反馈；
- 增加引用准确率、来源定位准确率和无答案准确率测试。

### 阶段 4：知识治理和版本管理

目标：让知识内容具备可审核、可发布、可失效和可审计的生命周期。

计划：

- 草稿、审核、发布、下线状态；
- 文档负责人、审核人、适用公司、适用项目和有效期限；
- 文档版本和索引版本关联；
- 默认只检索正式且生效版本；
- 新版本发布后的旧版本降权或过滤；
- 发布前测试问答、变更影响分析、恢复和审计记录。

### 阶段 5：评测和反馈闭环

目标：用固定数据和用户反馈衡量改动是否真正改善问答。

计划：

- 建立 BIM 业务黄金问题集；
- 覆盖规范、客户标准、公司标准、培训视频、表格、多轮追问、跨主题切换和无答案问题；
- 统计 Recall@1、Recall@5、MRR、引用准确率、无答案准确率、追问关联率、P50/P95 延迟和 Token 成本；
- 保存原始问题、改写问题、检索来源、最终引用、模型和 Prompt 版本；
- 将低质量反馈转成回归测试；
- 对切片、Embedding、Reranker、Prompt 和改写策略做版本比较。

### 阶段 6：BIM/CAD 专项能力

目标：形成通用 RAG 平台不具备的专业知识能力。

计划：

- Revit 族、参数、楼层、视图、系统和模型对象索引；
- DWG/DXF 图纸编号、专业、版本和区域元数据；
- 图纸 OCR、区域引用和模型对象 ID 引用；
- 规范条文与模型检查结果关联；
- BIM/CAD 专项问答和模型检查评测集。

## 统一问答数据契约

后续阶段优先采用以下语义，而不是继续扩展裸字符串字段：

```text
QueryResolution
  original_query
  standalone_query
  kind: standalone | follow_up | clarification_required | topic_switch
  confidence
  referenced_turns
  fallback_reason
```

回答链路应分别记录：

```text
original_query
standalone_query
retrieved_sources
reranked_sources
model_context_sources
cited_sources
answer
```

这样可以直接回答“系统检索了什么、看到了什么、最终引用了什么、为什么这样回答”。

## 验证和回滚

- 阶段 1、2 属于 RAG 行为变化，必须先跑单问题冒烟，再跑固定黄金集；
- 前端或 SSE 字段变化必须同步后端 Schema、类型、解析器和组件测试；
- 不修改既有索引契约前无需重建索引；如修改 Chunk、Embedding、Payload 或 Collection，必须重新审批并说明重建和回滚；
- 每个阶段保持独立提交，行为变化可通过回退对应提交恢复；
- 不使用真实客户文档、真实对话、API Key 或生产数据作为测试资产。

## 实施顺序

```text
阶段 0 基线调查
  -> 阶段 1 追问上下文
  -> 阶段 2 检索质量
  -> 阶段 3 回答引用
  -> 阶段 4 知识治理
  -> 阶段 5 评测闭环
  -> 阶段 6 BIM/CAD 专项
```

阶段 0 完成后，进入阶段 1 前应再次确认结构化 `QueryResolution` 的字段和澄清策略；阶段 1 之后再决定是否扩大到阶段 2 的检索策略改造。
