# 分层查询增强候选方案

- 状态：待审批
- 范围：查询拆分、MQE 与受控 HyDE
- 性质：候选设计，不代表现有能力或实施授权

## 目标

在保留规范编号、客户名称、型号和精确参数检索能力的前提下，改善口语化表达、术语错配、故障现象和培训视频问题的召回率，同时避免 HyDE 假设内容削弱 no-answer 判断。

## 当前基础

- 查询守卫、多轮独立问题改写和原始 Dense + Sparse + code boost 已实现。
- 比较意图查询拆分和真实 `retrieve_multi` 已实现，但默认关闭，仍待 Phase A 生产评测和灰度决策。
- 多子查询最低配额、跨查询融合、全局 rerank、拆分感知上下文预算和 rerank 批量上限已实现。
- MQE 与 HyDE 尚未实现。

## 候选路由

1. 所有请求先经过现有查询守卫和多轮改写。
2. 规范编号、条款号、客户名、型号或精确参数查询只走原始检索通道。
3. 比较或合并多个实体时优先复用查询拆分。
4. 可能存在术语错配时，生成 2～3 个语义等价 MQE 查询。
5. 故障现象、操作经验或培训视频问题仅在低置信度时加入一个 HyDE Dense 通道。
6. 原始查询始终保留为最高可信通道；HyDE 不进入 Sparse 或 code boost。

## 实施顺序

- 先完成查询拆分 Phase A 生产评测和灰度决策。
- 再在术语错配黄金集上独立试验 MQE。
- 最后以默认关闭的实验开关加入 HyDE。
- 只有固定黄金集证明收益且延迟、成本可接受，才扩大触发范围。

## 验证门槛

- 补充术语错配、模糊现象、培训视频、规范编号、精确数值和跨领域 no-answer 用例。
- 分类型比较 Recall@1、Recall@5、MRR、no-answer 保持率和多主题覆盖率。
- 记录 P50/P95 延迟、每轮 LLM 调用次数与 Token 成本。
- 规范编号、客户标准和精确参数类不得退化。

## 风险与兼容性

MQE/HyDE 会改变 RAG 行为、延迟和成本，属于 R2。候选方案不修改 Chunk、Embedding 或索引 Schema，按当前设想无需重建索引；如果后续改变这些契约，必须重新评级和审批。
