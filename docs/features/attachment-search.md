# 附件检索与图片 OCR

## 状态与边界

元数据检索和文件卡已通过 [PR #840](https://github.com/abworks-dev/RAGPinCheng/pull/840) 交付，生产证据为 [App 部署运行](https://github.com/abworks-dev/RAGPinCheng/actions/runs/41821874699)。自然语言多条件匹配及受控本地 OCR 启用为本次增量；其实际启用状态以当前部署运行的验证结果为准，不以源码默认值推断。用户验收仍待确认。依赖[多格式附件与轻量预览](<attachment-previews.md>)和[对话运行时](<chat-runtime.md>)。

- 检索文件名、标题、分类路径、描述、标签、项目、别名及已完成的图片 OCR 文本；这是元数据与文字检索，不是视觉理解、模型属性问答或工程计算。
- 仅发现未归档、当前已发布 head，且分类及祖先均允许聊天检索的附件；显式空分类范围返回空结果。草稿、旧版本、禁用分类、归档附件及失效 OCR 不能作为当前命中。
- 不把附件/OCR 写入 Parent、Embedding 或 Qdrant，不构造 `SourceDTO` 或伪造引用；文件卡与知识回答来源独立。OCR 文本不作为文件请求的 LLM 回答上下文。
- 不自动回填历史图片 OCR；启用后按新上传/发布及显式任务入口处理，失败、取消和禁用不影响附件本身可用性。
- 找文件长句先经固定词法规则拆分硬条件，例如“帮我寻找一个地下室一层含开闭所的案例图纸”保留楼层和开闭所两个条件，所有条件必须命中；支持地下室一层/地下一层/负一层/B1 等 1–9 层写法。原始明确文件名优先，项目、数字标识及目录范围不能随意丢弃；不支持的否定条件或超过 12 个条件直接无匹配，不放宽为无关结果。这不是模型语义理解，也不读取 DWG/RVT 图形内容。
- 目录名称从当前分类树动态匹配，改名、移动及祖先禁用即时反映，不依赖重建 OCR 索引。优先级为精确文件名、文件名/标题、人工元数据、目录、OCR；结果有上限但不先截断任意前 500 个目录候选。宽泛目录查询可能检查该目录中较多附件，实际容量仍需部署环境验证。

本次增量的本地集成回归为 410 项及 2 个子测试通过；[Linux CI](https://github.com/abworks-dev/RAGPinCheng/actions/runs/41827653172) 已验证禁网、只读文件系统 OCR 容器的真实中文识别和鉴权。受控启用通过 [PR #841](https://github.com/abworks-dev/RAGPinCheng/pull/841) 收口；生产部署与用户验收不能由这些合成技术验证替代。

## 调用链与契约

```text
受管附件 + 版本检索元数据 / 当前有效 OCR 文本
 -> app.sqlite 附件检索与当前可见性过滤
 -> ChatSession 注入式搜索 / 独立附件搜索接口
 -> file_results 文件卡 -> 受控信息 / 预览 / 下载
图片 -> OCR 队列与 worker -> 独立本地 OCR HTTP 服务 -> 版本绑定结果
```

- [搜索实现](<../../api/content_search.py>)、[OCR 任务](<../../api/image_ocr_jobs.py>)、[窄接口](<../../api/routes_attachment_search.py>)；[服务实现](<../../services/image_ocr/app.py>)、[运行与许可证边界](<../../services/image_ocr/README.md>)及[可选 Compose](<../../docker/docker-compose.image-ocr.yml>)。
- `GET /api/attachments/search` 接收 `query`、可选分类 key 列表 `categories`、`limit`；返回 `results`。聊天通过 `ChatSession` 搜索原问题和改写问题、按版本去重；明确找文件及可重验的“第二个附件”使用确定性文件回复，不进入模型解析。知识问答保持原 RAG 编排，并附独立文件卡。
- `FileResultDTO` 包含 item/version ID、标题、原文件名、类型、大小、分类 key/路径、版本号、命中字段、片段、预览类型和预览/下载能力。SSE `prep`/`done`、消息及回答版本均有默认空数组 `file_results`；不得与 `sources` 混用。
- [运行时](<../../api/conversation_runtime.py>)把卡片写入消息及回答版本并恢复；刷新、重生成/编辑和序号追问沿用版本链，展示与引用旧卡前按当前权限、head、分类和归档状态重验，不把历史 JSON 当作授权。
- 管理端 `search-info` / `search-metadata` 编辑描述、标签、项目与别名；`ocr` 查询/入队，`ocr/cancel` 取消。写操作保留权限与 CSRF 校验，OCR 更新以有效 job/head 为准。

## 权限与预览边界

登录聊天用户可通过聊天最小能力发现、读取当前允许聊天检索附件的信息与预览；这不授予全局 `item.view`，不扩大资料管理列表权限。原管理端入口继续使用自己的权限。

`/api/attachments/versions/{version_id}/info`、`/preview`、`/download` 每次重新检查当前可见性；下载还必须具备 `item.download`。不可见附件返回 404，未登录或未授权由后端拒绝，不能靠历史卡片或直接 URL 绕过。

图片/DXF/IFC 原生预览必然向浏览器发送必要源字节，不是 DRM，也不承诺禁止保存。RVT/DWG 等不透明附件的预览只能是人工关联图片/PDF，不能借预览接口读取无下载权限的原文件；预览失败有明确降级。

## 配置与验证

集中配置见 [config](<../../src/config.py>)：`ATTACHMENT_SEARCH_ENABLED=true`；`IMAGE_OCR_ENABLED=false`。OCR 默认 URL 为 `http://image-ocr:8091`，请求超时 30 秒，输入上限 33554432 字节、80000000 像素。OCR 服务独立部署并使用内部鉴权；令牌通过安全配置提供，不在文档/日志输出。关闭 OCR 不关闭元数据检索；关闭附件搜索不删除已存数据或执行索引 Reset。

验证入口：[搜索与权限](<../../tests/test_attachment_search.py>)、[OCR 队列](<../../tests/test_image_ocr_jobs.py>)、[OCR 服务](<../../tests/test_image_ocr_service.py>)、[聊天单元](<../../tests/test_attachment_chat.py>)、[真实端口合成集成](<../../tests/test_attachment_chat_integration.py>)、[前端组件](<../../frontend/src/components/attachment-search.test.tsx>)及[浏览器夹具](<../../frontend/tests/visual/attachment-search.spec.ts>)。本地聊天/版本回归 20 项通过；OCR 服务本地 12 项通过，包含实际中文 UTF-8、空白与英文图片；另用后端真实 HTTP 客户端访问仅绑定回环地址的临时服务，合成图片识别出“消防通道项目110”，验证后已停止服务。父任务最终集成后端 15 文件 269 项通过；前端完整单元 65 文件 576 项通过、1 项既有跳过，构建通过。合成浏览器基线四种视口 52 项通过；文件卡成功状态修正后，桌面/移动定向 4 项再次通过，截图已检查。上述浏览器使用合成聊天夹具，不替代真实后端浏览器、远端 CI、生产验证或用户验收。

检索质量补测：6 个固定合成查询各执行 10 次，Recall@1=1.000、Recall@5=1.000、MRR=1.000，无命中保护 1/1；该微型夹具观测 p95=0.332 ms。它只证明这些精确名称/元数据/目录/OCR 排序用例，不代表真实语料覆盖率、端到端聊天时延或生产 SLA。

## 安全合成数据用户验收

目标：确认文件发现、文字召回、预览及权限一致，不误称知识引用或视觉分析。验收规则见[用户验收规范](<../USER_ACCEPTANCE.md>)。

前置条件：管理员已准备获批的独立测试环境与当前构建；搜索启用。需要验证 OCR 时，由管理员在该环境启用并确认内部 OCR 服务健康；未准备好则标记 OCR 步骤未执行。准备可上传/发布的管理员、无下载权限的普通聊天账号和有下载权限账号，使用桌面及移动宽度浏览器。

数据：两张包含“合成测试甲/乙”的非敏感 JPG/PNG（如“图片11.png”“图片12.png”）、一个小型合成 DWG/RVT 附件及人工关联 PNG。不使用客户资料或真实模型。

1. 管理员从资料库上传并发布测试附件，设置明确描述、项目、标签和别名。
   - 预期：元数据保存；未发布版本不会在普通聊天检索出现。
2. 普通账号进入聊天，输入“帮我找图片11”，再按描述或别名查找附件；同时检查独立附件搜索入口。
   - 预期：展示正确版本文件卡而非伪引用；找文件回复不声称解析图像或模型。纯数字输入仍受查询保护。
3. 两个附件同时命中后输入“打开第二个附件”，刷新会话，再重生成或编辑问题。
   - 预期：定位对应卡片；当前回答及版本卡正确恢复，知识来源仍独立。
4. 预览图片、关联预览及测试环境已有的 DXF/IFC 合成样例；对比两种下载权限账号。
   - 预期：无下载权限仍可获得必要预览字节，但没有原文件下载授权；不透明模型只提供关联预览。关闭、重开和失败降级可理解，移动端不遮挡。
5. OCR 测试环境对合成图片提交任务，等待终态，再检索图片内独特文字；另用空白图片和失败/取消样例检查状态。
   - 预期：有效 OCR 文字可召回；空白不捏造文字，失败/取消不阻断附件；没有 OCR 时仍能按元数据搜索。不要求历史图片自动回填。
6. 管理员仅在独立测试环境关闭测试分类的聊天检索，随后普通账号刷新旧会话及重试直接预览 URL。
   - 预期：对应文件卡被当前可见性过滤，直接请求被拒绝；祖先关闭同样生效。未登录访问受保护端点应被拒绝，管理写入缺 CSRF 也应失败。

清理与回滚：恢复测试分类开关；停止测试任务后按测试夹具生命周期销毁独立环境。共享测试资料由管理员按既有回收站流程处理，不把物理删除、生产迁移、Reset 或生产部署作为普通验收。配置回滚只在获批测试环境恢复原开关，不删除原文件或索引。

失败时请提供步骤编号、脱敏截图/错误文字、浏览器、角色、时间和最短复现；不提供令牌、Cookie 或业务资料。完成后请明确回复“验收通过”或失败步骤；未获明确确认不能声明用户验收通过。
